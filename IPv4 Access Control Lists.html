2. What is an IPv4 ACL?

An Access Control List (ACL) is a sequence of rules configured on a router or Layer 3 device to control traffic based on specified conditions.

Incoming Packet
→
ACL Check
→
Permit / Deny

PERMIT

The packet is allowed to continue processing.

DENY

The packet is blocked by the ACL.

ORDER MATTERS

ACL statements are checked from top to bottom.

IMPLICIT DENY

There is an invisible deny any at the end of an ACL.

Important: If no ACL entry matches the packet, the implicit deny causes the packet to be denied.

Standard ACL → WHO? (source address)

4. Wildcard Mask

Wildcard masks are commonly used in Cisco ACLs to identify which bits of an IPv4 address must match.

Wildcard Bit Meaning
0 Must match
1 Ignore this bit

Common Examples

Network Subnet Mask Wildcard Mask
192.168.1.0/24 255.255.255.0 0.0.0.255
192.168.1.0/26 255.255.255.192 0.0.0.63
10.0.0.0/8 255.0.0.0 0.255.255.255
Formula:
Wildcard Mask = 255.255.255.255 − Subnet Mask

5. Standard IPv4 ACL

A Standard ACL filters traffic primarily using the source IPv4 address.

Example Scenario

PC-A
192.168.1.10
ROUTER
R1
SERVER
192.168.2.10
Waiting for packet...

Example Requirement

Allow host 192.168.1.10 to access the network. 

R1(config)# access-list 10 permit host 192.168.1.10
R1(config)# access-list 10 deny any

R1(config)# interface g0/0
R1(config-if)# ip access-group 10 in

Using Wildcard Mask

R1(config)# access-list 10 permit 192.168.1.0 0.0.0.255
Teaching Point: An ACL number alone does not activate the ACL. The ACL must be applied to an interface using ip access-group.

6. Extended IPv4 ACL

Extended ACLs provide much more detailed traffic control.

Source IP

Who is sending?

Destination IP

Who is receiving?

Protocol

TCP, UDP, ICMP, etc.

Port

HTTP 80, HTTPS 443, DNS 53, SSH 22, etc.

Example

Allow users from 192.168.1.0/24 to access a web server 192.168.2.10 using HTTP. 

R1(config)# access-list 100 permit tcp 192.168.1.0 0.0.0.255 host 192.168.2.10 eq 80

8. ACL Processing Order

Cisco evaluates ACL statements sequentially from the top to the bottom.

Packet Arrives
→
ACL Entry 1
→
ACL Entry 2
→
ACL Entry 3
→
Implicit Deny
First Match Wins!
Once a packet matches an ACL statement, processing stops.

Example

access-list 10 deny host 192.168.1.10
access-list 10 permit 192.168.1.0 0.0.0.255

Host 192.168.1.10 is denied because it matches the first statement. Other hosts from 192.168.1.0/24 can be permitted by the second statement.

9. Important ACL Keywords

Keyword Meaning Example
host Matches one IPv4 address host 192.168.1.10
any Matches all IPv4 addresses permit ip any any
eq Matches a specific port eq 80
tcp Matches TCP traffic permit tcp
udp Matches UDP traffic permit udp
icmp Matches ICMP traffic permit icmp

10. Named IPv4 ACL

Named ACLs are easier to manage because the ACL is identified by a descriptive name.

Standard Named ACL

R1(config)# ip access-list standard STUDENT_ACCESS
R1(config-std-nacl)# permit host 192.168.1.10
R1(config-std-nacl)# deny any
R1(config-std-nacl)# exit

R1(config)# interface g0/0
R1(config-if)# ip access-group STUDENT_ACCESS in

Extended Named ACL

R1(config)# ip access-list extended WEB_ACCESS
R1(config-ext-nacl)# permit tcp 192.168.1.0 0.0.0.255 host 192.168.2.10 eq 80
R1(config-ext-nacl)# deny ip any any
R1(config-ext-nacl)# exit

11. Cisco IOS ACL Configuration

Step 1: Create Standard ACL

R1(config)# access-list 10 permit 192.168.1.0 0.0.0.255

Step 2: Apply ACL to Interface

R1(config)# interface g0/0
R1(config-if)# ip access-group 10 in

Step 3: Verify ACL

R1# show access-lists
R1# show ip interface g0/0

Extended ACL Example

R1(config)# access-list 100 permit tcp 192.168.1.0 0.0.0.255 host 192.168.2.10 eq 80

R1(config)# interface g0/1
R1(config-if)# ip access-group 100 in
Recommended classroom sequence: Create ACL → Apply ACL → Generate Traffic → Verify ACL Counters.

12. Inbound vs Outbound ACL

Inbound

The ACL examines the packet when it enters the router interface. 

interface g0/0
ip access-group 100 in

Outbound

The ACL examines the packet before it leaves the router interface. 

interface g0/1
ip access-group 100 out
Simple analogy:
Inbound ACL = Security check at the entrance.
Outbound ACL = Security check at the exit.

13. Where Should ACLs Be Placed?

ACL Type General Placement Principle
Standard ACL Usually closer to the destination because it filters mainly by source address.
Extended ACL Usually closer to the source because unwanted traffic can be stopped early.
These are general design guidelines. Actual placement depends on the network topology, security requirement, and traffic flow.

17. Quick Assessment

Q1. What does an ACL primarily provide?
A. Packet filtering
B. IP address assignment
C. DNS resolution
Correct: A — ACLs are used for traffic filtering and access control.
Q2. Which ACL type can filter using TCP/UDP port numbers?
A. Standard ACL
B. Extended ACL
C. Static route
Correct: B — Extended ACLs can filter using protocol and port information.
Q3. What happens when no ACL statement matches?
A. Permit
B. Implicit deny
C. Broadcast
Correct: B — ACLs have an implicit deny at the end.
Q4. What does wildcard bit 0 mean?
A. Ignore the bit
B. Must match the bit
C. Deny the bit
Correct: B — 0 means the corresponding bit must match.
Q5. Which command applies an ACL to an interface?
A. ip access-group 10 in
B. ip route 10
C. access-enable 10
Correct: A — The ACL must be applied using ip access-group.

  • ACLs control IPv4 traffic.
  • Standard ACLs primarily examine source IPv4 addresses.
  • Extended ACLs can examine source, destination, protocol and ports.

  • First matching statement determines the action.
  • There is an implicit deny at the end.
  • Wildcard masks are important for network matching.
  • An ACL must be applied to an interface to affect traffic.
