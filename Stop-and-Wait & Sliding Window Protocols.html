Stop-and-Wait & Sliding Window Protocols

Data Link Layer | Flow Control | Error Control | ARQ

📡 What are Flow Control Protocols?

Flow control manages the rate at which a sender transmits data so that a receiver is not overwhelmed by incoming frames.

Two important approaches are:

  • Stop-and-Wait Protocol
  • Sliding Window Protocol
Basic Difference:

Stop-and-Wait → Send one frame, then wait.

Sliding Window → Send multiple frames before waiting for all acknowledgments.

🛑 1. Stop-and-Wait Protocol

🔐 Stop-and-Wait ARQ

Stop-and-Wait ARQ combines stop-and-wait flow control with error recovery using acknowledgments and retransmissions.

1 ACK

ACK confirms successful reception of a frame.

2 Timeout

If the expected ACK does not arrive within the timeout period, the sender retransmits.

3 Sequence Number

A small sequence-number field can help distinguish new frames from duplicates after retransmission.

🪟 2. Sliding Window Protocol

A Sliding Window Protocol allows the sender to transmit multiple frames before receiving acknowledgments for every frame.

Example:

Window Size = 4

Sender can transmit: Frame 0, Frame 1, Frame 2, Frame 3 before needing to stop and wait for all four ACKs.

⚖️ Stop-and-Wait vs Sliding Window

Feature Stop-and-Wait Sliding Window
Frames in Transit Usually one Multiple
ACK Handling Wait after each frame Multiple frames can be outstanding
Efficiency Lower on high-delay links Higher when configured appropriately
Implementation Simple More complex
Window Size Effectively 1 Greater than 1
Throughput Limited by RTT Better utilization of the link

📚 Important Sliding Window Protocols

1 Go-Back-N

If a frame is lost or damaged, the sender retransmits that frame and subsequent unacknowledged frames.

Error at Frame 2 → Resend 2, 3, 4...

2 Selective Repeat

Only the missing or damaged frame is retransmitted.

Error at Frame 2 → Resend only 2

3 Flow Control

The receiver's available capacity can influence how much data the sender is allowed to have outstanding.

🚀 Why Use Sliding Window?

Stop-and-Wait:
Send → Wait → ACK → Send → Wait → ACK

Sliding Window:
Send → Send → Send → Send → ACKs arrive

Sliding-window protocols can keep the communication link busy instead of leaving it idle while waiting for each acknowledgment.

🧠 Simple Classroom Example

A
Stop-and-Wait: Send Frame 1 → Wait for ACK 1 → Send Frame 2 → Wait for ACK 2.
B
Sliding Window: Send Frame 1, 2, 3 and 4 → receive ACKs while transmission continues.

🎯 Easy Way to Remember

  • Stop-and-Wait: One frame → Wait → ACK → Next frame.
  • Sliding Window: Multiple frames → ACKs → Window moves.
  • Window Size: Determines how many frames can be outstanding.
  • Go-Back-N: Retransmit the lost frame and subsequent unacknowledged frames.
  • Selective Repeat: Retransmit only the lost/damaged frame.
Memory Trick:

Stop-and-Wait = One at a Time
Sliding Window = Many at a Time
