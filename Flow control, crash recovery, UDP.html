1. What is Flow Control?

Flow control is a mechanism used to prevent a fast sender from sending data faster than the receiver can process.

Simple idea:

Fast Sender → 🚗🚗🚗🚗🚗🚗
Slow Receiver → 🚶

Without flow control, the receiver's buffer can become full.

Real-Life Example

Imagine filling a water bottle.

🚰
Fast Water Flow
→
🍼
Small Bottle

If the tap is opened too much, the bottle may overflow. Similarly, if a sender transmits too quickly, the receiver's buffer may overflow.

2. TCP Flow Control

TCP uses a mechanism called the Receive Window (rwnd) to implement flow control.

Receiver Window = 5000 bytes Sender can send approximately 5000 bytes before needing additional acknowledgment/window information.

Basic Concept


Sender                         Receiver

   |                               |
   | ---- Data ------------------> |
   |                               |
   | <--- ACK + Window = 5000 ---- |
   |                               |
   | ---- Data ------------------> |
   |                               |
Important: The receiver tells the sender how much additional data it can accept.

4. Flow Control vs Congestion Control

Feature Flow Control Congestion Control
Protects Receiver Network
Problem Fast sender / slow receiver Too much network traffic
Example Receiver buffer becoming full Routers becoming overloaded
TCP Receive Window Congestion Window
Remember:

Flow Control → "Can the receiver handle this?"
Congestion Control → "Can the network handle this?"

5. Crash Recovery

A system crash can occur because of:

  • Power failure
  • Operating system failure
  • Hardware failure
  • Network failure
  • Application crash
When a computer crashes during communication, the sender and receiver may lose information about the current communication state.

Example


Sender                         Receiver

   |                               |
   | ---- DATA ------------------> |
   |                               |
   | <--------- ACK -------------- |
   |                               |
   |                               X
   |                         💥 CRASH
   |
   | ---- DATA ------------------> |

After the crash, the system may need to determine:

  • Which data was successfully received?
  • Which data was lost?
  • Should data be retransmitted?
  • Is the connection still valid?

6. Techniques Related to Crash Recovery

Technique Purpose
Sequence Numbers Identify data and detect duplicates
Acknowledgments Confirm successful reception
Timeout Detect possible lost data
Retransmission Send lost data again
Connection Re-establishment Create a new connection when necessary
Checksums Detect corrupted data

8. What is UDP?

UDP stands for User Datagram Protocol.

UDP is a connectionless transport-layer protocol.

UDP

Fast • Simple • Low Overhead • Connectionless

UDP sends independent datagrams without establishing a TCP-style connection first.

9. UDP Header

The UDP header is only 8 bytes.

Field Size Purpose
Source Port 16 bits Identifies sending process
Destination Port 16 bits Identifies receiving process
Length 16 bits Total UDP datagram length
Checksum 16 bits Error detection
UDP Header = 8 Bytes +-----------------------+ | Source Port | 16 bit | +-----------------------+ | Destination | 16 bit | +-----------------------+ | Length | 16 bit | +-----------------------+ | Checksum | 16 bit | +-----------------------+

10. Characteristics of UDP

Feature UDP
Connection Connectionless
Reliability Not guaranteed by UDP
Ordering Not guaranteed
Retransmission Not provided by UDP itself
Flow Control Not provided by UDP itself
Congestion Control Not provided by UDP itself
Header Size 8 bytes
Speed / Overhead Low overhead

11. Where is UDP Used?

DNS
DNS commonly uses UDP for ordinary queries because the exchange can be small and connection setup would add unnecessary overhead.
DHCP
DHCP uses UDP because a host may need network configuration before it has a normal IP-based connection.
VoIP
Voice applications often prefer low delay rather than retransmitting old voice packets.
Online Gaming
Games may prefer low latency and can tolerate some packet loss depending on the game.
Video / Live Streaming
Real-time applications may prioritize continuous delivery and low delay.

14. Important Concept

TCP: "I will establish a connection, maintain state, acknowledge data, retransmit when necessary, and provide ordered reliable delivery."

UDP: "I will send the datagram with minimal transport overhead. Delivery, ordering, and retransmission are not guaranteed by UDP itself."

16. Interview Quick Revision

1. What is flow control?

Flow control regulates the sender's transmission rate so that the receiver is not overwhelmed.

2. What is the difference between flow control and congestion control?

Flow control protects the receiver, while congestion control manages traffic to reduce network congestion.

3. What is crash recovery?

Crash recovery deals with restoring or re-establishing communication after a system or connection failure.

4. How can TCP detect lost data?

TCP uses mechanisms including sequence numbers, acknowledgments and timers/timeouts to detect possible loss and trigger retransmission.

5. What is UDP?

UDP is a connectionless transport-layer protocol that provides datagram delivery with low protocol overhead.

6. What is the size of the UDP header?

The UDP header is 8 bytes.

7. Does UDP provide flow control?

UDP itself does not provide TCP-style flow control.

8. Does UDP provide retransmission?

UDP itself does not provide retransmission. If an application needs reliability, it can implement appropriate mechanisms at a higher layer.

9. Why is UDP used for real-time applications?

Many real-time applications prioritize low delay and may prefer to avoid the retransmission and connection-management overhead associated with TCP.

10. Give examples of UDP applications.

DNS, DHCP, VoIP, online gaming and many real-time media applications can use UDP.
