1. TCP Three-Way Handshake
Describe the three-way handshake protocol used for connection establishment in TCP.
Answer

TCP is a connection-oriented protocol. Before actual data transmission begins, TCP establishes a reliable connection between the sender and receiver.

CLIENT SERVER | | | -------- SYN --------------> | | | | <----- SYN + ACK ----------- | | | | -------- ACK --------------> | | | | Connection Established |

Step 1 – SYN

The client sends a SYN segment to the server. It indicates that the client wants to establish a connection.

Step 2 – SYN + ACK

The server responds with SYN + ACK. It acknowledges the client's request and sends its own initial sequence number.

Step 3 – ACK

The client sends an ACK to acknowledge the server's response. The TCP connection is now established.

Remember: SYN → SYN + ACK → ACK
2. TCP Connection Release and Two-Army Problem
Illustrate the process of connection release in TCP protocol with an analogy of the Two-Army Problem.
Answer

TCP connection termination is generally performed using four control messages because TCP communication is full-duplex.

CLIENT SERVER | | | -------- FIN --------------> | | | | <-------- ACK -------------- | | | | <-------- FIN -------------- | | | | -------- ACK --------------> | | | | Connection Closed |
  1. The client sends FIN indicating that it has finished sending data.
  2. The server sends ACK.
  3. The server sends its own FIN after completing its communication.
  4. The client sends the final ACK.

Two-Army Problem

Imagine two armies located on opposite sides of a valley. They want to coordinate an attack using an unreliable messenger.

Army A | | "Attack at 10 AM" ↓ Army B | | "Message received" ↓ Army A

Army A cannot obtain absolute certainty that Army B received the final confirmation because the communication channel may lose messages.

The Two-Army Problem illustrates the difficulty of achieving absolute certainty over an unreliable communication channel.
3. RIP and Distance Vector Routing
Apply distance vector routing concepts to explain how RIP exchanges routing information and updates routing tables in routers.
Answer

RIP stands for Routing Information Protocol. It is a distance-vector routing protocol that uses hop count as its metric.

R1 -------- R2 -------- R3 | | LAN1 LAN3

Suppose R2 informs R1 that LAN3 is one hop away from R2. R1 adds one hop to reach R2.

R1 → R2 → LAN3 = 2 hops
Destination Distance Next Hop
LAN1 0 Direct
LAN2 1 R2
LAN3 2 R2

RIP routers exchange routing information and update their routing tables when a better route is discovered.

Important: RIP considers 16 hops as unreachable.
4. Count-to-Infinity Problem
Demonstrate the occurrence of count-to-infinity problem in distance vector routing and explain how it can be addressed.
Answer

The count-to-infinity problem occurs when routers continue increasing the metric to a destination that has actually become unreachable.

A -------- B -------- X Suppose X fails. B → X = 3 A → X = 4 B → X = 5 A → X = 6 B → X = 7 ... 16 → Unreachable

Solutions

  • Split Horizon: A router does not advertise a route back through the interface from which it learned the route.
  • Poison Reverse: The router advertises the route with an infinite metric.
  • Route Poisoning: A failed route is immediately marked unreachable.
  • Hold-Down Timer: Temporarily prevents unstable routing information from being accepted.
5. TCP Congestion Control and Timer Management
Explain how TCP controls the congestion and manages the timer.
Answer

TCP uses congestion control to prevent excessive traffic from overloading the network.

Slow Start

1 → 2 → 4 → 8 → 16 Rapid increase in congestion window

Congestion Avoidance

16 → 17 → 18 → 19 → 20 Gradual increase

Fast Retransmit

When TCP receives multiple duplicate acknowledgements, it assumes that a segment has been lost and retransmits the segment without waiting for the retransmission timer.

TCP Timer

Send Segment | ↓ Start Timer | ↓ ACK received? / \ YES NO | | Stop Timeout Timer | ↓ Retransmit

TCP uses a retransmission timer to detect lost segments. Other timers include persist, keepalive and TIME-WAIT timers.

6. Flooding in Computer Networks
Illustrate the different ways of achieving flooding in a computer network and the limitations in each of them.
Answer

Flooding is a routing technique in which a packet is forwarded through multiple outgoing paths.

1. Uncontrolled Flooding

The router forwards the packet through all outgoing interfaces except the incoming interface.

Limitation: Creates duplicate packets and may cause congestion.

2. TTL / Hop Count

A packet is assigned a limited lifetime.

TTL = 5 5 → 4 → 3 → 2 → 1 → 0 | Drop

Limitation: A packet may expire before reaching the destination.

3. Sequence Numbers

Each packet is given a unique sequence number. Routers remember packets that have already been processed.

Limitation: Requires memory to store sequence information.

4. Selective Flooding

The router forwards packets only through selected interfaces that are likely to lead toward the destination.

Limitation: Requires additional routing information.

7. IPv4 Access Control List
Apply IPv4 Access Control List (ACL) concepts to configure network security rules for allowing and denying specific traffic.
Answer

An ACL is a set of rules configured on a router to control network traffic.

PC1 = 192.168.1.10 PC2 = 192.168.1.20 Server = 10.0.0.10 Requirement: Allow PC1 Deny PC2

Example Standard ACL

Router(config)# access-list 10 permit host 192.168.1.10
Router(config)# access-list 10 deny any

Router(config)# interface gigabitEthernet 0/0
Router(config-if)# ip access-group 10 in

Extended ACL Example

access-list 100 deny tcp host 192.168.1.20
host 10.0.0.10 eq 80

The above rule can deny HTTP traffic from PC2 to the server.

ACL rules are processed from top to bottom. The first matching rule is applied.
8. TCP Transmission Policy and Silly Window Syndrome
Analyze the TCP transmission policy and the occurrence and avoidance of Silly Window Syndrome.
Answer

TCP uses the sliding-window mechanism to control how much data can be transmitted before acknowledgements are received.

Silly Window Syndrome

Silly Window Syndrome occurs when very small amounts of data are repeatedly transmitted.

Inefficient: 1 byte → Send 1 byte → Send 2 bytes → Send 1 byte → Send Better: [1 + 1 + 2 + 1] bytes → Send

Causes

  • Receiver advertises very small windows.
  • Application produces very small amounts of data.

Solutions

  • Clark's Solution: Receiver avoids advertising very small windows.
  • Nagle's Algorithm: Sender combines small amounts of data before transmission.
9. Token Bucket Algorithm and QoS
Explain how Token Bucket algorithm can improve the Quality of Service (QoS) in a network.
Answer

The Token Bucket algorithm is used for traffic shaping and traffic policing.

Tokens Added ↓ ┌──────────────┐ │ ● ● ● ● ● ● │ │ TOKEN BUCKET │ └───────┬──────┘ ↓ Packets ↓ Network

Tokens are generated at a specified rate. A packet requires a sufficient number of tokens before it can be transmitted.

QoS Benefits

  • Controls bandwidth usage.
  • Reduces congestion.
  • Allows controlled bursts.
  • Improves traffic predictability.
  • Supports better network resource management.
Token Bucket: Controls the average traffic rate while allowing controlled bursts when tokens are available.
10. Spanning Tree for Multicast Routing
Apply the concept of spanning tree for multicast routing in a computer network. Give a suitable example.
Answer

Multicast communication allows one source to send data to multiple receivers.

R1 | R2 / \ R4 R3 | R5 Source → R2 ↙ ↘ R4 R3 | R5

A multicast distribution tree provides a loop-free path between the source and multiple receivers.

Example – University Live Lecture

Suppose a university broadcasts a live lecture from a central video server to several student networks.

Video Server | Router / \ / \ Student A Router | Student B | Student C

Instead of sending separate copies over every possible path, the network can use shared links in the multicast distribution tree.

Advantages

  • Reduces duplicate traffic.
  • Saves bandwidth.
  • Provides loop-free forwarding.
  • Efficient for one-to-many communication.
Applications: Live lectures, IPTV, video streaming, online meetings, and software distribution.
