Techniques to Improve QoS

Leaky Bucket Algorithm • Token Bucket Algorithm

1. What is QoS?

QoS (Quality of Service) refers to techniques used to provide predictable and controlled network performance for different types of traffic.

QoS can help manage:
  • Bandwidth
  • Delay
  • Jitter
  • Packet loss
  • Traffic priority

Why is QoS Important?

Different applications have different requirements.

Application Important Requirement
Voice / VoIP Low delay and low jitter
Video Conferencing Low delay, sufficient bandwidth
Online Gaming Low latency
Email Reliability is generally more important than very low delay
File Transfer High throughput and reliability

3. Leaky Bucket Algorithm

The Leaky Bucket algorithm controls traffic by allowing packets to leave at a relatively fixed rate.

Think about a bucket with a small hole at the bottom.

Water may enter quickly, but water leaves through the hole at a controlled rate.

4. How Leaky Bucket Works

  1. Packets enter the bucket.
  2. The bucket has a fixed capacity.
  3. Packets leave at a controlled rate.
  4. If packets arrive faster than the bucket can accommodate, the bucket can become full.
  5. Additional packets may be discarded if the buffer is full.
Property Leaky Bucket
Output Rate Approximately constant
Burst Handling Buffers bursts, then smooths output
Bucket Overflow Packets may be discarded
Traffic Pattern Smooth / controlled
Important: The classic leaky bucket algorithm produces a controlled output rate and does not normally allow accumulated bursts to be released faster than the configured leak rate.

6. Token Bucket Algorithm

The Token Bucket algorithm works differently from the Leaky Bucket.

Tokens are generated at a specified rate and stored in the bucket up to a maximum capacity. A packet can be transmitted when sufficient tokens are available.

7. How Token Bucket Works

  1. Tokens are generated at a configured rate.
  2. Tokens accumulate in the bucket.
  3. The bucket has a maximum token capacity.
  4. A packet consumes one or more tokens depending on the configured model / packet size.
  5. If enough tokens exist, the packet can be transmitted.
  6. If insufficient tokens exist, the packet waits or is handled according to the implementation/policy.
Major Advantage: Token Bucket can allow controlled bursts when tokens have accumulated.
Property Token Bucket
Token Generation At a configured rate
Bucket Capacity Maximum number of tokens
Burst Traffic Can be allowed if tokens have accumulated
Rate Control Controlled by token availability

9. Leaky Bucket vs Token Bucket

Feature Leaky Bucket Token Bucket
Basic Idea Packets leave at a controlled rate Packets transmit when tokens are available
Output Approximately smooth / fixed Average rate controlled, bursts possible
Burst Traffic Generally smoothed Can allow bursts if tokens are available
Bucket Contains Packets / queued traffic Tokens
Overflow Packets may be dropped when queue is full Excess tokens are discarded when bucket is full
Best Mental Model Water leaking through a hole Coins/tokens granting permission to send

10. Easy Example: Leaky Bucket

Suppose:

Bucket capacity = 10 packets
Leak rate = 2 packets/second
Incoming burst = 8 packets

The 8 packets enter the bucket, but they do not all leave simultaneously. They are transmitted at approximately: 


Time 0 → 2 packets
Time 1 → 2 packets
Time 2 → 2 packets
Time 3 → 2 packets
The burst is converted into a smoother output stream.

11. Easy Example: Token Bucket

Suppose:

Token generation rate = 2 tokens/second
Bucket capacity = 10 tokens
Packets need 1 token each.

If the bucket has accumulated 8 tokens, a short burst of up to 8 packets can potentially be transmitted immediately, subject to the implementation and other network limits.

13. How These Algorithms Improve QoS

  • Reduce sudden traffic bursts.
  • Control the average traffic rate.
  • Reduce the probability of congestion.
  • Help manage available bandwidth.
  • Improve predictability of network traffic.
  • Help protect network resources from excessive bursts.
Important: Leaky Bucket and Token Bucket are primarily traffic shaping/policing mechanisms. They are components of QoS, but QoS as a whole also includes scheduling, classification, queuing, priority handling and other mechanisms.

15. Interview Questions

Q1. What is QoS?

QoS is a collection of techniques used to manage network traffic and provide predictable service characteristics such as bandwidth, delay, jitter and packet-loss performance.

Q2. What is traffic shaping?

Traffic shaping controls the rate at which packets are transmitted, often smoothing bursts before traffic enters the network.

Q3. What is the Leaky Bucket algorithm?

Leaky Bucket is a traffic-shaping algorithm that queues incoming packets and releases them at a controlled rate.

Q4. What happens if the Leaky Bucket becomes full?

Depending on the implementation, additional packets may be discarded when the bucket/queue has no available space.

Q5. What is the Token Bucket algorithm?

Token Bucket generates tokens at a configured rate. Packets can be transmitted when sufficient tokens are available.

Q6. What is the major advantage of Token Bucket?

It can allow controlled bursts when tokens have accumulated while maintaining a controlled long-term average rate.

Q7. Which algorithm is better for smoothing traffic?

Leaky Bucket is commonly associated with producing a smoother, controlled output rate.

Q8. Which algorithm allows bursts?

Token Bucket can allow bursts when enough tokens have accumulated.

Q9. What does a token represent?

A token represents permission to transmit a unit of traffic under the configured token-bucket model.

Q10. What is the easiest way to remember them?

Leaky Bucket:
Packets go out at a controlled rate.

Token Bucket:
Tokens give permission to send.
