1. Why Does TCP Need Timers?

TCP provides reliable delivery. When TCP sends a segment, it needs to know whether the segment or its acknowledgment has been lost.

Basic idea:

TCP sends data → starts a timer → waits for ACK.

If ACK arrives → timer is handled accordingly.
If the timer expires before sufficient acknowledgment → TCP assumes possible loss and may retransmit. 

Sender                         Receiver

  | -------- DATA ------------> |
  |                             |
  |       START TIMER           |
  |                             |
  | <----------- ACK ----------- |
  |                             |
  |       ACK RECEIVED          |

2. TCP Retransmission Timer

The retransmission timer is used to detect when an acknowledgment has not arrived within an appropriate period.

Sender
💻
→
Network
🌐
→
Receiver
🖥️

After sending a segment, TCP measures network behavior and maintains a retransmission timeout value, commonly called RTO.

If the expected ACK is not received before the relevant timer expires, TCP can retransmit the segment.

3. RTT – Round Trip Time

RTT is approximately the time taken for a segment to travel to the receiver and for the corresponding acknowledgment to return. 


Sender                         Receiver

  | -------- DATA ------------> |
  |                             |
  |                             |
  | <----------- ACK ----------- |
  |                             |

<----------- RTT ------------->
RTT = Round Trip Time

It is an important measurement used when estimating TCP's retransmission timeout.

4. RTO – Retransmission Timeout

RTO is the amount of time TCP waits before concluding that a retransmission may be necessary because the expected acknowledgment has not arrived.

RTO should not simply be a fixed value for every network. A short RTO may cause unnecessary retransmissions. A very long RTO may delay recovery from actual packet loss.

Conceptual Relationship


Measured RTT
     ↓
TCP estimates RTT variation
     ↓
Retransmission Timeout (RTO)
     ↓
Timer used for loss detection

Modern TCP implementations use smoothed RTT and RTT variation rather than simply setting RTO equal to one RTT measurement.

6. What Happens When a Timeout Occurs?


Sender                         Receiver

  | -------- DATA ------------> |
  |                             |
  |        TIMER START          |

  |          X                  |
  |       ACK LOST              |

  |                             |
  | -------- DATA ------------> |
  |       RETRANSMIT            |
Timeout → Possible loss → Retransmission

After a retransmission timeout, TCP also adjusts its congestion behavior. In classic TCP congestion-control algorithms, a timeout is a strong indication of congestion and causes the congestion window to be reduced significantly.

7. Other TCP Timers

Timer Purpose
Retransmission Timer Detect possible loss when an expected ACK does not arrive.
Persist Timer Helps prevent a zero-window deadlock by probing the receiver.
Keepalive Timer Can detect an idle peer that may no longer be reachable, when enabled.
TIME-WAIT Timer Controls how long a closed TCP connection remains in TIME-WAIT.

8. What is TCP Congestion Control?

TCP congestion control regulates how much data can be outstanding in the network so that TCP does not overwhelm the network.

Flow Control: Protects the receiver.

Congestion Control: Protects the network.

TCP mainly uses two important variables:

  • cwnd – Congestion Window
  • ssthresh – Slow-Start Threshold

9. Congestion Window – cwnd

The congestion window (cwnd) limits the amount of data TCP can have in flight based on its estimate of network congestion.

Current Congestion Window:

1 MSS
Larger cwnd → TCP can have more data in flight.

Smaller cwnd → TCP reduces its sending rate.

10. Slow Start

Despite its name, TCP Slow Start can increase the congestion window rapidly at the beginning of a connection or after certain congestion events.

In simplified teaching models: cwnd approximately doubles each RTT during Slow Start. 

RTT 1 → 1 MSS
RTT 2 → 2 MSS
RTT 3 → 4 MSS
RTT 4 → 8 MSS
RTT 5 → 16 MSS

When cwnd reaches ssthresh, TCP typically transitions to congestion avoidance.

11. Congestion Avoidance

During congestion avoidance, TCP increases its congestion window more gradually than in Slow Start.

A common simplified model is: approximately +1 MSS per RTT. 

8 → 9 → 10 → 11 → 12 → 13 ...

The exact behavior depends on the TCP congestion-control algorithm and implementation.

12. TCP Congestion Control Phases

Slow Start Congestion Avoidance Fast Retransmit Fast Recovery

Phase Main Idea
Slow Start Rapidly increase cwnd from a small initial value.
Congestion Avoidance Increase cwnd more cautiously.
Fast Retransmit Retransmit after enough duplicate ACKs indicate likely loss.
Fast Recovery Reduce and then cautiously increase cwnd after certain loss signals.

13. Fast Retransmit

TCP can detect a likely missing segment when it receives multiple duplicate acknowledgments. 


Sender                         Receiver

  | ---- Segment 1 ----------> |
  | ---- Segment 2 ----------> |
  | ---- Segment 3 ----------> |   X LOST
  | ---- Segment 4 ----------> |
  |                             |
  | <------- ACK 3 ------------ |
  | <------- ACK 3 ------------ |
  | <------- ACK 3 ------------ |

       Duplicate ACKs

            ↓

       Fast Retransmit
Key idea: Enough duplicate ACKs can indicate that a segment was probably lost, allowing retransmission without waiting for the retransmission timer.

14. Fast Recovery

Fast Recovery is associated with congestion-control algorithms that respond to loss indicated by duplicate ACKs without reducing the congestion window as drastically as a timeout.

A timeout is generally treated as a stronger indication of congestion than duplicate ACKs. 

Duplicate ACKs
      ↓
Fast Retransmit
      ↓
Reduce cwnd
      ↓
Fast Recovery
      ↓
Continue cautiously

15. Timeout vs Duplicate ACKs

Event Typical Interpretation Typical TCP Response
Timeout Strong indication of loss/congestion Reduce cwnd significantly; restart with Slow Start behavior
Duplicate ACKs Likely isolated segment loss Fast Retransmit and congestion response
Remember: Timeout → Stronger congestion signal.

Duplicate ACKs → Earlier loss indication.

21. Interview Questions

Q1. Why does TCP use a retransmission timer?

To detect possible segment loss when an expected acknowledgment does not arrive within the estimated retransmission timeout.

Q2. What is RTT?

RTT is the approximate time required for a segment to travel to the receiver and for the corresponding acknowledgment to return.

Q3. What is RTO?

RTO is the retransmission timeout used by TCP to determine when a retransmission may be necessary.

Q4. What is cwnd?

cwnd is the congestion window. It limits the amount of unacknowledged data TCP can have in flight based on congestion-control state.

Q5. What is ssthresh?

ssthresh is the slow-start threshold used to determine when TCP should transition from Slow Start toward Congestion Avoidance in the traditional model.

Q6. What is Slow Start?

Slow Start is a TCP congestion-control phase in which cwnd grows rapidly from a small value, approximately doubling each RTT in the simplified model.

Q7. What is Congestion Avoidance?

Congestion Avoidance increases cwnd more cautiously than Slow Start. A common simplified model is approximately one MSS per RTT.

Q8. What is Fast Retransmit?

Fast Retransmit allows TCP to retransmit a likely lost segment after receiving enough duplicate ACKs, without waiting for the retransmission timer to expire.

Q9. What is Fast Recovery?

Fast Recovery is a congestion-control response used by relevant TCP algorithms after loss indicated by duplicate ACKs, allowing the sender to reduce its sending rate without treating the event exactly like a retransmission timeout.

Q10. What is the easiest way to remember TCP congestion control?

Slow Start → Grow quickly
Congestion Avoidance → Grow carefully
Duplicate ACKs → Fast Retransmit
Timeout → Strong reduction
