2. ARP — Finding Physical Address from Logical Address

IP → MAC

ARP (Address Resolution Protocol) maps an IPv4 logical address (IP address) to the destination's physical address (MAC address) on the local network.

Host A checks its ARP cache for 192.168.1.20.
If no entry exists, Host A broadcasts an ARP Request on the LAN.
Host B recognizes its IP address and sends an ARP Reply containing its MAC address.
Host A stores the IP-to-MAC mapping in its ARP cache.
The Ethernet frame is then addressed to Host B's MAC address.
ARP mapping: 192.168.1.20 → BB-BB-BB
Important: ARP is used for IPv4. IPv6 uses Neighbor Discovery Protocol (NDP) instead of ARP.

6. NAT — Multiple Private Hosts Using One Public IP

Private → Public

NAT (Network Address Translation) translates private IP addresses inside a local network into public addressing used on the Internet.

A private host sends a packet to an Internet destination.
The NAT router replaces the private source address with its public address.
The Internet sees the public address, not the private source address.
For return traffic, the router uses its translation state to deliver the response to the correct internal host.
With PAT: many private hosts can share one public IP by using different source port numbers.

9. DHCP Process — Obtaining an IP Address

DORA

DHCP automatically provides a host with an IP address and other network parameters such as subnet mask, default gateway and DNS server.

StepMessagePurpose
1DHCPDISCOVERClient broadcasts to locate DHCP servers.
2DHCPOFFERServer offers an IP address and configuration.
3DHCPREQUESTClient requests the offered address.
4DHCPACKServer confirms the lease and supplies configuration parameters.
Example: Client receives IP 192.168.1.20, subnet mask 255.255.255.0, gateway 192.168.1.1 and a DNS server address.

10. Tunnelling Across Heterogeneous Networks

Encapsulation

Tunnelling carries packets of one protocol through a network that uses another protocol by encapsulating the original packet inside a new packet.

A source host creates an original packet, for example an IPv6 packet.
The tunnel-entry router encapsulates the original IPv6 packet inside an IPv4 packet.
The IPv4 network forwards the outer packet as normal IPv4 traffic.
The tunnel-exit router removes the outer IPv4 header (decapsulation).
The original IPv6 packet is forwarded to the destination IPv6 network.
Before tunnel: [ IPv6 Header | IPv6 Data ] Inside heterogeneous IPv4 network: [ IPv4 Header | IPv6 Header | IPv6 Data ] After tunnel: [ IPv6 Header | IPv6 Data ]
Applications: IPv6-over-IPv4 transition, VPNs such as IPsec tunnels, and connecting networks that use different addressing or transport environments.
Key idea: Tunnelling = encapsulate → transport through another network → decapsulate.
